# Next-Key Lock 范围判断

## 你会学到什么

[`03-gap-lock`](../03-gap-lock/) 演示了间隙锁会挡住范围内的插入，但没说清楚
"范围"到底是怎么算的——等值查询命中已有值、等值查询没命中、开区间范围，三种
`WHERE` 条件锁住的间隙形状完全不一样。这个 demo 用三组实测，把每种情况到底锁住
哪个区间钉死。

## 原理

`points` 表在 `idx_val` 上只有三个值：10、20、30。InnoDB 的 next-key lock 是
"记录锁 + 它前面那段间隙"的组合，但等值查询命中已有值时，InnoDB 还会**额外**
锁住这条记录后面的间隙，防止别的事务插入第二条相同值——不然对同一个等值条件
再查一次会多出一行，也是一种幻读。三种情况锁住的区间：

- **等值命中已有值**（`val = 20`）：锁住 `(10, 20)` + 记录 `20` + `(20, 30)`——
  两侧的间隙都锁，不只是"前面"那一段。
- **等值没命中任何值**（`val = 15`）：只锁住这个值本该落在的那一个间隙
  `(10, 20)`，两侧都没有记录可锁，自然也不会往两边扩。
- **开区间范围**（`val > 20`）：锁住记录 `30` 的 next-key（`(20, 30]`），再加上
  最后一条记录之后的间隙 `(30, +∞)`——InnoDB 用一个叫 **supremum** 的伪记录
  代表"索引的末尾"，范围没有上界时这段也会被锁住。

## 复现

准备数据：

```bash
../../client.sh < setup.sql
```

打开两个独立的 client 会话：

```bash
../../client.sh -D nk_lab   # session A
../../client.sh -D nk_lab   # session B
```

### 场景 1：等值命中（`val = 20`）

1. **session A** 执行 `session_a_hit.sql`。
2. **session B** 依次执行 `session_b_hit.sql` 里的四条 `INSERT`，逐条观察：
   `val=9` 立刻成功，`val=15` 和 `val=25` 都会阻塞（超时报 1205），`val=35`
   立刻成功。
3. 回 **session A** 执行 `ROLLBACK`。

### 场景 2：等值未命中（`val = 15`）

重置数据（`../../client.sh < setup.sql`），跑 `session_a_miss.sql` +
`session_b_miss.sql`：`val=12` 阻塞，`val=25` 立刻成功——只锁了一个间隙。

### 场景 3：开区间（`val > 20`）

重置数据，跑 `session_a_range.sql` + `session_b_range.sql`：`val=15` 立刻
成功，`val=25` 和 `val=35` 都阻塞——范围之外的间隙完全不受影响，范围没有上界
时连"末尾之后"的间隙也锁住。

## 结论

- 间隙锁不是简单地"锁住 WHERE 条件里写的那个区间"，而是取决于索引里实际存在
  哪些记录——等值命中会把命中记录两侧的间隙都锁上，等值未命中只锁一个间隙。
- 开区间范围没有上界时，会一路锁到 supremum，也就是这张表在这个索引上"最大
  值之后"的间隙，任何比当前最大值还大的插入都会被挡住，直到事务提交或回滚。
- 排查"明明没查到冲突行，为什么插入被卡住"这种问题时，先确认锁定语句是等值
  还是范围、命中没命中——这决定了锁住的间隙边界在哪。
